-   **P0 --- Must Have:** Required for the core solution and demo.
-   **P1 --- High Value:** Strong differentiators after P0 is stable.
-   **P2 --- Nice to Have:** Build only if time remains.

## 6. Feature Prioritization Rule

A feature should be added only when it: 1. Directly solves a PS
requirement or important user pain point. 2. Provides measurable user
value. 3. Is feasible within the remaining time. 4. Does not destabilize
P0 functionality.
